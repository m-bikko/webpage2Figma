# html2design — дизайн-документ

**Дата:** 2026-09-19
**Статус:** утверждён, готов к планированию реализации

## 1. Что строим

Инструмент из двух половин, который снимает **страницу, открытую в браузере пользователя** — вместе с состоянием авторизации и текущим состоянием интерфейса — и превращает её в редактируемый макет Figma: пять готовых экранов под разные дисплеи плюс библиотека компонентов.

Аналог `html.to.design` от divriots, с двумя отличиями по замыслу: (а) осмысленные компоненты вместо плоской горы фреймов, (б) явный отчёт о том, что перенести не удалось, вместо молчаливо неверного результата.

**Аудитория:** внутренняя команда. Публикации в Chrome Web Store и Figma Community не будет, биллинга и бэкенда тоже. Распространение — собранный артефакт плюс README.

## 2. Ограничение платформы, задающее форму системы

Figma REST API **не умеет создавать содержимое файла**: он читает файлы, пишет только комментарии и переменные. Единственный способ породить фреймы, слои и компоненты — плагин, исполняющийся внутри Figma (Plugin API).

Следствие: система обязательно состоит из двух исполняемых артефактов и транспорта между ними. Это не выбор архитектуры, а свойство платформы.

## 3. Архитектура

```
┌─ Chrome Extension (MV3) ─────────────────────────────┐
│  popup UI        выбор размеров, режима, опций
│  service worker  оркестратор: CDP-эмуляция, сбор, сборка бандла
│  page probe      обход DOM в MAIN world (+ опц. слой C)
│  serializer      DOM → IR                    ← чистая функция
│  resource fetch  картинки/шрифты, с cookies пользователя
│  normalizer      >4096px, AVIF/WebP → PNG
└──────────────────────┬───────────────────────────────┘
                       │  bundle.h2d  (ZIP: ir.json + assets/ + screenshots/)
                       ▼
┌─ Figma Plugin ───────────────────────────────────────┐
│  UI (iframe)     file input, выбор экранов, прогресс, отчёт
│  validator       строгая схема IR → внятная ошибка
│  font preloader  loadFontAsync ДО создания текста
│  layout inferrer IR → auto-layout | absolute  ← чистая функция
│  node builder    IR → Frame/Text/Rect/Vector
│  component synth слой B: повторы → Component + инстансы
│  page organizer  раскладка по страницам Figma
└──────────────────────────────────────────────────────┘
```

### 3.1 Транспорт — файл, а не сервер

Выбран файл-бандл `.h2d` (ZIP: `ir.json` + `assets/` + `screenshots/`), который extension скачивает, а плагин принимает через `<input type="file">`.

Альтернатива — localhost WebSocket-relay — даёт «один клик» вместо двух, но добавляет фоновый процесс на машине каждого коллеги, `allowedDomains` в манифесте плагина и целый класс сетевых сбоев. Файл детерминирован, воспроизводится, прикладывается к багрепорту и переживает перезапуск Figma. Для команды без публикации это строго лучше.

Версия IR штампуется в бандл. Несовпадающие половины отказываются работать с внятным сообщением, а не ломаются тихо.

### 3.2 Результат в Figma — четыре страницы

| Страница | Содержимое |
|---|---|
| `Screens` | 5 фреймов подряд: 1920 / 1440 / 1024 / 768 / 390 |
| `Components` | библиотека найденных компонентов; инстансы на экранах ссылаются сюда |
| `Tokens` | Variables из CSS custom properties, Text Styles, Paint Styles |
| `Report` | всё, что не удалось перенести, со ссылками на узлы |

## 4. Получение пяти размеров

На экране в данный момент существует одна ширина. Остальные четыре надо получить, и это самая дорогая развилка проекта.

### 4.1 Режим A — CDP-эмуляция (основной)

Service worker цепляется к активной вкладке через `chrome.debugger` и последовательно вызывает `Emulation.setDeviceMetricsOverride` на каждую из пяти ширин. Браузер честно пересчитывает layout: срабатывают media queries, container queries, `ResizeObserver`, обработчики ресайза. После каждого ресайза ждём стабилизации и снимаем DOM.

Плюс: пять настоящих макетов. Живой JS, живая авторизация, вкладка не перезагружается, состояние SPA (открытая модалка, заполненная форма) сохраняется.

Минус: нужен `debugger`-permission и Chrome рисует плашку «DevTools is debugging this tab». Захват последовательный, примерно в пять раз дольше одного.

**Требование надёжности:** `chrome.debugger.detach` и сброс `Emulation` выполняются в `finally`. Вкладка пользователя ни при каком сбое не остаётся в эмуляции.

### 4.2 Режим B — offscreen-iframe (fallback «не трогай мою вкладку»)

Снимаем страницу один раз, клонируем захваченный HTML и CSS в пять скрытых iframe'ов разной ширины, читаем computed styles из каждого. Media queries отрабатывают честно — это настоящий CSS в настоящем iframe. Но JS не переигрывается: layout, который дорисовывает скрипт, и lazy-контент приедут в desktop-виде на мобильной ширине.

Один движок захвата, два драйвера размеров.

### 4.3 Отклонённый вариант

Пять скрытых окон с реальной навигацией отклонены: это перезагрузка, теряющая текущее состояние страницы после кликов — ровно то, зачем нужен инструмент. Плюс реальное окно Chrome не сжать до 390px.

### 4.4 Дефолтные размеры

| Экран | Размер | Назначение |
|---|---|---|
| Desktop XL | 1920 × 1080 | максимальная ширина, проверка max-width контейнеров |
| Desktop | 1440 × 900 | базовый макет |
| Tablet L | 1024 × 1366 | iPad Pro portrait, малый ноутбук |
| Tablet | 768 × 1024 | iPad portrait, частый отдельный брейкпоинт |
| Mobile | 390 × 844 | iPhone 14/15 |

Список редактируется в popup.

## 5. Компоненты

### 5.1 Слой B — эвристика по повторам DOM (ядро)

Ищем повторяющиеся поддеревья с одинаковой структурной подписью (`tag` + сигнатура классов + форма детей). Что встретилось два и более раз — становится `Figma Component`, остальные вхождения — инстансами с override'ами текста и изображений.

Параллельно извлекаются токены: CSS custom properties → Figma Variables, повторяющиеся комбинации шрифт/кегль/интерлиньяж → Text Styles, палитра заливок → Paint Styles.

Работает на любом сайте, включая чужие и не-React. Это фундамент, а не опция.

### 5.2 Слой C — интроспекция фреймворка (экспериментальный, по умолчанию выключен)

Если на странице есть `__REACT_DEVTOOLS_GLOBAL_HOOK__` или `__VUE__`, обход fiber-дерева даёт настоящие имена и границы компонентов (`ProductCard`, `Button`, `NavItem`) вместо «div повторился шесть раз», а props становятся кандидатами в Component Properties.

**Это приватный недокументированный API.** Форма fiber менялась между React 16/17/18/19, а в минифицированном проде имена компонентов превращаются в `t` и `Xr`. Поэтому слой C архитектурно изолирован: это один дополнительный проход, который умеет ровно две вещи — **переименовать** узел и **пометить** границу компонента. Он не строит геометрию, не трогает стили, не создаёт слои. Исключение или мусор на выходе — проход отбрасывается целиком, результат равен чистому слою B.

Флаг в UI, по умолчанию выключен, подписан «экспериментально».

### 5.3 Отклонённый вариант

Правила под конкретные дизайн-системы (`ant-btn`, `MuiButton-root`, shadcn `data-slot`) отклонены по YAGNI: слой C даёт то же самое общим способом, а покрытие правил узкое.

## 6. IR — промежуточное представление

Контракт между половинами и единственное, что действительно надо спроектировать правильно. Версионированный JSON, не знающий ни о DOM, ни о Figma.

```ts
Bundle   { version, capturedAt, url, title, userAgent,
           screens: Screen[], assets: Asset[],
           fonts: FontRequirement[], tokens: Tokens,
           report: Diagnostic[] }

Screen   { name, width, height, dpr, root: Node, screenshotId }

Node     { id, sourceTag, name,
           rect: { x, y, w, h },        // абсолютные координаты документа
           paintOrder: number,          // порядок отрисовки, НЕ порядок DOM
           layout: { mode: 'row'|'column'|'none', gap, padding, align, justify, wrap },
           style: { fills, strokes, radius, shadows, opacity, blend, clip },
           text?:  { runs: TextRun[], lines: LineBox[] },
           image?: { assetId, fit },
           children: Node[] }
```

**`IrNode` — размеченное объединение по `kind`** (`frame` | `text` | `image` | `vector` | `placeholder`). Это результат design-ревью: без дискриминатора состояние «и текст, и картинка» представимо и бессмысленно, исчерпывающий `switch` из §8.5 невозможен, а заглушке для неподдерживаемого содержимого нечем быть.

Три решения внутри структуры, каждое закрывает известный источник расхождений.

**`paintOrder` отдельным полем.** Порядок слоёв в Figma — это порядок отрисовки браузера, определяемый stacking contexts и `z-index`, а не порядком в DOM. Это самая частая причина «импортировалось, но всё перекрыто не тем». Правила CSS-стекинга специфицированы и детерминированы, поэтому резолвер стекинга — отдельный чистый модуль с полным юнит-покрытием.

**`text.lines` рядом с `text.runs`.** Текста и шрифта недостаточно: Figma переносит строки сама и почти наверняка иначе, чем браузер. Реальные боксы строк снимаются через `Range.getClientRects()`, расхождение ловится и попадает в отчёт.

**`report` — полноправная часть бандла, а не лог.** Всё неподдерживаемое становится записью отчёта **и** видимой заглушкой в Figma с именем вида `⚠ unsupported: canvas`.

## 7. Границы поддержки

### 7.1 Переносим уверенно

Геометрия; сплошные заливки; обводки, включая разную толщину по сторонам и стиль `dashed`/`dotted` → `dashPattern`; радиусы по углам; тени внешние и внутренние; `opacity`; `overflow: hidden` → `clipsContent`; типографика — семейство, кегль, вес, `line-height`, `letter-spacing`, выравнивание, декорации, `text-transform` (применяется к самой строке), `text-shadow`; `display: flex`/`grid` → auto-layout; открытый shadow DOM; same-origin iframe (рекурсивно).

### 7.1b Переносим в плане 2; в плане 1 обязательно диагностируется

Раздел появился после design-ревью контракта IR. Первая редакция спеки перечисляла эти фичи в §7.1 как уверенно переносимые, но контракт не имел для них ни одного поля, а сериализатор не порождал диагностики. Получался ровно запрещённый правилом §8.5 исход: градиентный блок приезжал прозрачным, повёрнутый — раздутой осепараллельной коробкой, inline-иконка исчезала, и никто об этом не узнавал.

Правило для всего в этом разделе: **пока фича не реализована, встреча с ней обязана порождать `Diagnostic`** и, где применимо, видимую заглушку. Поля в контракте для них уже есть — `transform`, `blend`, `blur`, `kind: 'vector'`, размеченный `Fill` — заполняются в плане 2.

- Градиенты: linear, radial, conic → `GradientPaint`. Добавляются членом размеченного объединения `Fill`, поэтому расширение безопасно: неизвестный `kind` падает громко и в zod, и в исчерпывающем `switch`.
- `transform` translate/rotate/scale → `Transform`. Внимание на инвариант: при непустом `transform` поле `rect` означает **не**трансформированный border box, иначе оно противоречит `getBoundingClientRect`, который отдаёт габарит уже трансформированного элемента.
- `mix-blend-mode` → `blendMode`.
- `filter: blur` → Layer Blur, `backdrop-filter: blur` → Background Blur.
- inline SVG → `kind: 'vector'`.
- Псевдоэлементы `::before`/`::after`.
- Изображения: `background-image` и `<img>` с полным размещением, а не только keyword'ом `cover`/`contain`/`repeat`.

### 7.2 Неподдерживаемое: заглушка плюс запись в отчёт

`<canvas>` и WebGL; cross-origin iframe; closed shadow DOM; `clip-path` и CSS-маски; SVG-фильтры; `filter` кроме blur; skew и 3D-трансформы (в Figma их нет физически); `repeating-*` градиенты; кастомные скроллбары; состояния `:hover`/`:focus`/`:active` (снимается покоящееся состояние); анимации и переходы (жанр — один кадр).

### 7.3 Осознанные компромиссы

**Скролл-контейнеры** приезжают с полным содержимым внутри и включённым клипом — дизайнер видит всё, сняв клип.

**Шрифты.** Плагин не может установить шрифт в Figma. При отсутствии семейства подбирается ближайший вес, при полном промахе подставляется Inter, и в отчёт идёт запись уровня error. Не установленные локально веб-шрифты — главный убийца точности, и отчёт про это должен кричать.

**`position: sticky`/`fixed`** снимаются в текущем скролл-положении и укладываются на место, с пометкой в отчёте.

**Нормализация ассетов.** `figma.createImage` принимает PNG/JPG/GIF и ограничен 4096px по стороне. AVIF и WebP конвертируются через `OffscreenCanvas`, крупные изображения масштабируются, факт масштабирования пишется в отчёт.

## 8. Стратегия корректности

Главное требование заказчика — «без ошибок и где точно уверен». Технически оно разворачивается в четыре уровня.

### 8.1 Чистое ядро и TDD

Сериализатор `DOM → IR`, резолвер стекинга и инферрер layout — чистые функции. Figma API и Chrome API спрятаны за адаптерами и мокаются. Тесты пишутся до кода.

### 8.2 Golden-фикстуры

По одному HTML-файлу на механизм CSS: flex-row, flex-wrap, grid, absolute, z-index-стекинг, перенос текста, тени, радиусы по углам, границы по сторонам, градиенты, псевдоэлементы, открытый shadow DOM, вложенный скролл, sticky. У каждой закоммичен эталонный IR. Playwright гоняет настоящий Chrome и диффит. Регрессия — красный CI.

### 8.3 Референс-рендерер и pixel-diff

Пишем рендерер `IR → SVG`. Цикл замыкается автоматически: Playwright снимает скриншот фикстуры на ширине W → тот же IR рендерится в SVG → скриншот SVG → `pixelmatch`, порог ≤0.5% отличающихся пикселей (настраивается на фикстуру).

Это доказывает, что **IR верно описывает то, что нарисовал браузер** — а там живёт почти сто процентов ошибок точности. Проверить так саму Figma нельзя: headless-рантайма у неё не существует. Проверить IR — можно полностью.

Бонусом рендерер становится инструментом отладки: открыл бандл, увидел, что сняли, ещё не заходя в Figma.

### 8.4 Round-trip проверка в Figma

В бандл кладётся по одному скриншоту на экран. Плагин умеет `exportAsync` построенный фрейм и показать его рядом с оригиналом. Расхождение видно глазом за секунду.

### 8.5 Правило, на которое есть тесты

**Молчаливый fallback — это баг.** Любая неподдерживаемая конструкция обязана породить `Diagnostic`. Фикстуры с неподдерживаемыми фичами утверждают наличие соответствующей записи.

Дополнительно: TypeScript strict, `noUncheckedIndexedAccess`, исчерпывающие `switch` по видам узлов IR, zod-валидация IR на границе плагина, запрет `any`.

## 9. Стек и структура репозитория

pnpm-воркспейс, TypeScript strict, без `any`.

Миграций версий IR **нет**: бандл — односверсионный артефакт, и отказ при несовпадении версий это правильное поведение для двух половин, которые всегда поставляются вместе. Обещание миграций из первой редакции спеки снято после design-ревью: строгий литерал `IrVersion` не позволяет типизировать функцию `migrate(old) → Bundle`, у которой в поле зрения обе формы, а сырой конверт `BundleEnvelope` нужен не для миграции, а чтобы сообщение об ошибке отличало «это не наш файл» от «наш файл чужой версии».

```
packages/ir                  типы + zod-схемы + миграции версий
packages/serializer          DOM → IR, чистый, исполняется в контексте страницы
packages/extension           MV3, Vite + @crxjs/vite-plugin, popup на React + antd
packages/figma-plugin        Vite; UI на React + antd, sandbox-код на TS
packages/reference-renderer  IR → SVG
fixtures/                    HTML + эталонные IR + скриншоты
```

Зависимости — только мейнстримные: `fflate` (ZIP), `zod` (валидация), `pixelmatch` и `pngjs` (диффы), `playwright`, `vitest`, `@crxjs/vite-plugin`, React, ant-design.

UI обеих половин — React + ant-design согласно приоритетам библиотек в глобальном `CLAUDE.md`. Перед написанием кода под antd, React и Vite документация запрашивается через context7.

## 10. Упаковка для команды

`pnpm build:all` даёт:

- `dist/extension.zip` — распаковать и поставить через «Load unpacked» в `chrome://extensions`
- `dist/figma-plugin/` — подключить в Figma через «Import plugin from manifest»
- `README.md` — установка на шесть шагов

Версия IR в бандле сверяется обеими половинами.

## 11. Что вне первой версии

Захват состояний `:hover`/`:focus` синтетическими событиями; localhost-relay вместо файла; правила под конкретные дизайн-системы; автоматизированный pixel-diff самой Figma (невозможен без headless-рантайма); публикация в сторы.
