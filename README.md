# webpage2figma

> **Сказать спасибо.** Инструмент бесплатный и таким останется. Если он сэкономил вам день — можно угостить автора кофе: [сумма любая, через Lemon Squeezy](https://qr-view.lemonsqueezy.com/checkout/buy/efde1ae5-6e09-4f5b-ab71-b492db80bf87).

Открытая в браузере страница — в том состоянии, в каком вы её видите: с авторизацией, раскрытыми меню, после скролла — становится макетом Figma с настоящими фреймами, текстовыми слоями, векторами, картинками и auto-layout. Пять брейкпоинтов за одну съёмку, и отчёт обо всём, что перенеслось приближённо.

Две части: **расширение Chrome** снимает страницу в файл `.w2f`, **плагин Figma** собирает из него слои. Ничего не уходит в сеть: у расширения нет сервера, у плагина сетевой доступ `none`.

## Инструкция по эксплуатации

### Установка

Готовый архив собирается командой `pnpm release` (см. [Разработка](#разработка)) или берётся из релиза: `webpage2figma-<версия>-team.zip`. Внутри `extension/`, `plugin/` и `INSTALL.md` с той же инструкцией.

**Расширение Chrome**

1. Распакуйте архив в постоянное место — например `~/Tools/webpage2figma/`. Chrome загружает расширение прямо из папки: переместите её — расширение пропадёт.
2. `chrome://extensions` → включите **Developer mode** (справа сверху) → **Load unpacked** → выберите папку `extension`.
3. Закрепите иконку: «пазл» на панели Chrome → булавка рядом с webpage2figma.

При запуске Chrome может показать плашку «Отключить расширения в режиме разработчика» — стандартное предупреждение для любого расширения не из магазина; «Отмена».

**Плагин Figma**

1. В десктопном приложении Figma откройте любой файл.
2. Меню → **Plugins → Development → Import plugin from manifest…** → выберите `plugin/manifest.json`.
3. Плагин появится в **Plugins → Development → webpage2figma**. Он виден только в вашем аккаунте — каждый ставит себе сам.

### Съёмка страницы

1. Откройте страницу и приведите её в нужное состояние: войдите в аккаунт, раскройте меню, доскролльте до нужной секции.
2. Нажмите на иконку расширения. Отметьте размеры, которые нужны — чем меньше, тем быстрее:

   | размер | вьюпорт |
   |---|---|
   | Desktop XL | 1920×1080 |
   | Desktop | 1440×900 |
   | Tablet L | 1024×1366 |
   | Tablet | 768×1024 |
   | Mobile | 390×844 |

3. **Снять страницу**. Во время съёмки Chrome показывает полосу «расширение отлаживает этот браузер» — так и должно быть: размер вьюпорта переключается через протокол отладки, другого способа получить настоящие медиазапросы нет. Полоса исчезает, когда съёмка закончена.
4. Файл `.w2f` скачивается в загрузки. Для небольшого захвата есть **Скопировать для Figma** — архив кладётся в буфер текстом, и файл искать не нужно. Если захват не пролезает, кнопка так и говорит: «слишком велик для буфера».
5. Под кнопками — отчёт о съёмке, сгруппированный по сообщениям со счётчиками. Он же целиком уезжает в файл.

Перед съёмкой расширение один раз проходит страницу прокруткой и возвращает её на место — иначе `loading="lazy"` ниже сгиба не успело бы загрузить картинки.

### Импорт в Figma

1. **Plugins → Development → webpage2figma**.
2. Выберите файл `.w2f` — или вставьте в поле то, что скопировала кнопка.
3. Каждый размер становится артбордом `<хост> — <размер> <ширина>`, например `tailwindcss.com — Desktop 1440`, с холстом страницы в заливке; артборды выложены в ряд.
4. Ниже в окне плагина — отчёт: что перенесено приближённо, что пропущено и почему, и отдельно — что стоит проверить глазами.

Что получается внутри артборда:

- Фреймы, прямоугольники, тексты, векторы (через тот же импортёр SVG, что при ручной вставке) и картинки — отдельными слоями с именами по сути: alt, заголовок, текст ссылки, семантический тег.
- Auto-layout там, где страница использовала flexbox **и** Figma разложила детей туда же, куда браузер, — это проверяется на месте, а не предполагается; иначе остаются абсолютные координаты и запись в отчёте.
- Невидимые обёртки схлопнуты: `div` без заливки, рамки и эффектов не становится пустым фреймом.

### Если что-то не так

- **«Бандл версии N, читатель понимает M»** — расширение и плагин разных версий. Формат односверсионный, миграций нет: обновите оба из одного архива и переснимите.
- **Расширение не загружается** — выбрана папка над `extension` или сам архив; внутри выбранной папки должен лежать `manifest.json`.
- **Плагина нет в меню** — Development-плагины видны только в аккаунте, который их импортировал.
- **Полоса «отлаживает браузер» не исчезла** — воркер упал между подключением и отключением отладчика; перезагрузите вкладку.
- **Картинка не приехала** — в отчёте будет причина: кросс-доменный источник, байты которого не отдались; не загрузившийся `<img>` (заглушка); картинка, которую не приняла Figma (лимит 4096 px на сторону) — узел остаётся без заливки, запись уровня error.

Точная граница переносимого — в [wiki/pages/concepts/support-boundaries.md](wiki/pages/concepts/support-boundaries.md): что переносится и проверяется pixel-diff, что откладывается с диагностикой, что не поддерживается (загрязнённый `<canvas>` и WebGL без буфера, `<video>`, кросс-доменные iframe, закрытый shadow DOM, частичный `clip-path`, SVG-фильтры, skew и 3D-трансформы, состояния `:hover`, анимации — снимается один кадр).

### Обновление

При установке из архива автообновлений нет: новый архив поверх старой папки → ↻ на карточке расширения в `chrome://extensions`; плагин просто перезапустить. Обновлять **вместе**. Публикация в Chrome Web Store и Figma Community (с автообновлениями) подготовлена: [docs/release/publishing.md](docs/release/publishing.md).

## Разработка

Node 20+, pnpm.

    pnpm install
    pnpm exec playwright install chromium
    pnpm build          # serializer → bundle → plugin → extension
    pnpm test           # typecheck + typecheck:root + build + unit + e2e

Расширение для разработки грузится как unpacked прямо из `packages/extension` (после `pnpm build`), плагин — `packages/plugin/manifest.json`. После пересборки: ↻ на карточке расширения, перезапуск плагина.

    pnpm release                 # версии, чистое дерево, pnpm test, артефакты в release/
    pnpm release --set 0.2.0     # поднять версию в четырёх файлах
    pnpm store-assets            # обложка и скриншоты для листингов

### Как устроено

```
packages/ir                  контракт IR: типы, zod-схема, инварианты, коды диагностик, IR_VERSION
packages/serializer          DOM → IR, исполняется внутри снимаемой страницы (IIFE)
packages/reference-renderer  IR → SVG: эталон для pixel-diff и кругового обхода
packages/bundle              архив .w2f: упаковка, распаковка, текстовая форма для буфера
packages/extension           расширение Chrome: брейкпоинты через chrome.debugger, ассеты, popup
packages/plugin              плагин Figma: IR → описание сцены → механический применитель
fixtures/                    HTML-фикстуры, IR-снапшоты, пороги pixel-diff с причинами
tests/e2e/                   Playwright: снапшоты, диагностики, pixel-diff, круговой обход, расширение
scripts/                     capture, verify-figma, verify-figma-nodes, release, store-assets
wiki/                        база знаний (Obsidian): решения, измерения, границы — читать первой
docs/release/                публикация, политика приватности, тексты листингов
```

Поток: расширение впрыскивает сериализатор в страницу для каждого брейкпоинта → `Screen` с деревом узлов и отчётом → байты ассетов и скриншот → архив `.w2f` → плагин строит из бандла `SceneSpec` (чистая функция, сравнимая в тестах) → применитель переносит его в Figma без вычислений, а для auto-layout сверяет раскладку Figma с ожидаемой и откатывает при расхождении.

### Единственное правило

Ничего не теряется молча. Всё, что не переносится точно, получает диагностику со стабильным кодом (`packages/ir/src/codes.ts`), и тест `codes-alive` требует, чтобы каждый код где-то порождался или был выведен из обращения с причиной. Пороги pixel-diff не подбираются — измеряются, записываются с причиной и проверяются сломом: в `threshold.json` каждой фикстуры сказано, какое число даёт сломанная реализация. Подробно — `wiki/pages/concepts/correctness-strategy.md`.

### Три проверки точности

1. **Pixel-diff** — фикстура снимается настоящим Chromium, IR рендерится обратно в SVG, растры сравниваются попиксельно с абсолютным бюджетом на пять ширин.
2. **Круговой обход** — бандл → сцена плагина → обратно в IR → SVG, сравнение с тем же скриншотом: ловит потери на стороне плагина.
3. **Сверка с Figma** — `pnpm verify-figma-nodes <файл.w2f> <ключ файла>` с `FIGMA_TOKEN` в окружении сравнивает импортированные узлы по REST API с построенной сценой: положение, размеры, текст, auto-layout, холст артборда. Figma — третий движок, и только здесь видно, где он расходится.

### Отладка без Figma

    pnpm capture https://example.com 1440 900
    pnpm capture fixtures/boxes/index.html

Кладёт в `out/`: `ir.json` (Screen и отчёт), `page.png` (браузер), `render.svg`/`render.png` (рендер IR) — сравнение глазами того, что автоматизирует pixel-diff.

### Типы

Ни одного `any` в `packages/` и `tests/`; strict плюс `noUncheckedIndexedAccess`. `grep -rn ": any\|as any" packages/ tests/` обязан молчать.
