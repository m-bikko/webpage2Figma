# Схема базы знаний webpage2figma

Obsidian-friendly база знаний проекта. Читается перед любым вопросом о проекте — раньше, чем поиск по коду.

## Структура

```
wiki/
├── CLAUDE.md           # этот файл: схема и инструкции
├── index.md            # каталог всех страниц по типам
├── log.md              # хронология операций
├── raw/assets/         # картинки, скриншоты, диаграммы
└── pages/
    ├── entities/       # сущности: модули, форматы, артефакты
    ├── concepts/       # концепции: архитектура, корректность, поддержка CSS
    ├── sources/        # саммари источников, инциденты
    └── analyses/       # ответы на вопросы, сравнения, решения
```

## Frontmatter

```yaml
---
title: Название страницы
type: entity | concept | source | analysis
tags: [тег1, тег2]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [пути или URL]
---
```

`updated:` поднимать при каждом редактировании. Даты в ISO. Относительные даты из реплик («вчера», «в четверг») конвертировать в абсолютные.

## Obsidian-конвенции

- Связи только через `[[wikilinks]]` — Graph View строится по ним. `[[ir-bundle]]`, `[[ir-bundle|формат бандла]]`, `![[diagram.png]]` для картинок из `raw/assets/`.
- Каждая страница должна иметь минимум одну входящую ссылку — минимум из `index.md`. Сироты в графе бесполезны.
- Умышленно битые wikilinks допустимы как отметка «страница ещё не написана».
- Теги в frontmatter попадают в Tag Pane.

## Именование

kebab-case, имена файлов на английском, контент на русском, технические термины не переводятся (`auto-layout`, `stacking context`, `paint order`, `fiber`).

## Что не писать

Git-историю, точные строки кода, эфемерное состояние задач, дубли того, что уже есть в `README.md` или `docs/superpowers/specs/` — на них давать ссылку.
