# Детекция компонентов

То, что отличает инструмент от `html.to.design`, где на выходе плоская гора фреймов. Два слоя с принципиально разным уровнем доверия.

## Слой B — эвристика по повторам DOM (ядро)

Ищутся повторяющиеся поддеревья с одинаковой структурной подписью: тег, сигнатура классов, форма детей. Встретилось два и более раз — становится `Figma Component`, остальные вхождения инстансами с override'ами текста и изображений.

Параллельно извлекаются токены: CSS custom properties в Figma Variables, повторяющиеся комбинации шрифт/кегль/интерлиньяж в Text Styles, палитра заливок в Paint Styles.

Работает на любом сайте, включая чужие и не-React. Это фундамент, а не опция.

## Слой C — интроспекция фреймворка (экспериментальный, по умолчанию выключен)

При наличии `__REACT_DEVTOOLS_GLOBAL_HOOK__` или `__VUE__` обход fiber-дерева даёт настоящие имена и границы компонентов вместо «div повторился шесть раз», а props становятся кандидатами в Component Properties.

**Почему изолирован.** Это приватный недокументированный API. Форма fiber менялась между React 16/17/18/19, в минифицированном проде имена компонентов превращаются в `t` и `Xr`. Уровень уверенности не позволяет ставить на него корректность продукта.

**Как изолирован.** Один дополнительный проход, умеющий ровно две вещи: **переименовать** узел и **пометить** границу компонента. Он не строит геометрию, не трогает стили, не создаёт слои. Исключение или мусор на выходе — проход отбрасывается целиком, результат равен чистому слою B.

Это архитектурная гарантия: поломка слоя C физически не может испортить импорт.

## Отклонено

Правила под конкретные дизайн-системы (`ant-btn`, `MuiButton-root`, shadcn `data-slot`) — слой C даёт то же самое общим способом, а покрытие правил узкое.
