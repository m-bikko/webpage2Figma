# Сверка импорта с Figma по REST API

`scripts/verify-figma-nodes.mjs`, команда `pnpm verify-figma-nodes <файл.w2f> <ключ файла> [id корня экрана]` с токеном в `FIGMA_TOKEN`. Сверяет **импортированный в Figma макет с бандлом — поузлово, без глаз.**

## Зачем, если есть пиксельный гейт и круговой обход

Оба сверяют наш SVG-рендер с браузером — и оба в Chromium. Что сделала с деревом **настоящая** Figma, они не видят: до этого скрипта только человек, глазами, по скриншоту (`pnpm verify-figma` — сравнение экспорта PNG с браузерным скриншотом, см. замеры в [[figma-semantics]]). Это та самая слепая зона между нашей моделью и настоящим API, где жили случаи 20–22 из [[correctness-strategy]]; REST-сверка делает её измеримой по форме результата, а не по картинке.

Токен — персональный, с правом `file_content:read`; никуда, кроме `api.figma.com`, не уходит и не сохраняется. Это единственное место проекта, где Figma REST API уместен: читать уже созданное, а не создавать — почему создавать через REST нельзя, см. [[why-not-rest-api]].

## Что сравнивается

Скрипт распаковывает бандл, строит из него сцену тем же `buildScene`, что и плагин (для этого у плагина есть самодостаточная сборка `dist/bundled.js` — по той же причине, что у `@w2f/bundle`: `exports` контракта указывают на `.ts`, и обычный Node их не прочитает), и обходит дерево Figma параллельно дереву сцены.

| что | как | допуск |
|---|---|---|
| положение | `absoluteBoundingBox` Figma против `origin + base.x/y` сцены (у Figma координаты абсолютные, у сцены — от родителя) | 1 пиксель: дробные координаты Figma округляет по-своему |
| размер | ширина и высота бокса | 1 пиксель; **не сверяется** у текста с `sizing: 'auto-width'` — он и должен отличаться, Figma меряет своим шрифтом |
| текст | тип узла `TEXT` и `characters` | точно |
| перенос однострочного | высота бокса `auto-width`-текста больше `lineHeight × 1.5` | — число строк есть то единственное, что круговой обход о тексте не проверяет ([[text-nodes]]) |
| вектор | тип узла из `VECTOR`/`FRAME`/`GROUP`/`BOOLEAN_OPERATION` | — |
| обводка | `strokeAlign === 'INSIDE'` у узла с обводкой | — |
| auto-layout | `layoutMode` не `NONE` у узла с раскладкой в сцене — иначе «auto-layout откатился» | — |
| число детей | совпадение длины | — |

Уровнем экрана сверяются **размер артборда** и его **первая заливка** против холста экрана ([[screen-canvas]]).

Сопоставление узлов — **по именам и порядку**: у Figma свои идентификаторы, а имена плагин выставляет из сцены, и на пути «сцена → applyNode → appendChild» порядок детей сохраняется. Расхождения выходят списком с путями по именам узлов, группируются по виду, самые частые сверху, печатаются первые тридцать.

## Как находится артборд

Экраны ищутся среди детей всех страниц файла (запрос с `depth=2`) по имени артборда из сцены — `<хост> — <экран> <ширина>`, см. [[scene-shaping]]. Из одноимённых берётся **последний** — последний импорт. Явный `id` корня третьим аргументом обходит поиск и ограничивает сверку одним экраном. Корень сцены (`body`) ожидается первым ребёнком артборда.

## 429

Лимит запросов Figma отдаёт как 429, и он не ошибка данных, а просьба подождать. Скрипт ждёт `retry-after` (или 30 секунд, умноженные на номер попытки) и повторяет до пяти раз, а не падает — иначе сверка срывалась бы на второй попытке подряд.

## Находка сверки с кодом (2026-09-22)

Итоговая строка по экрану печатает `figmaRoot.id`, а переменной `figmaRoot` в скрипте нет — артборд лежит в `artboard`. Строка выполняется после `compare`, то есть сверка первого экрана доходит до конца, а затем скрипт падает с `ReferenceError`, не дойдя ни до остальных экранов, ни до сводки по видам. Записано как долг, код не правился.
