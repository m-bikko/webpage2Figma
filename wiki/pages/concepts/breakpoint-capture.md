# Захват пяти брейкпоинтов

На экране в данный момент существует **одна** ширина. Остальные четыре надо получить — это самая дорогая развилка проекта. Реализованы два драйвера при одном движке захвата.

## Режим A — CDP-эмуляция (основной)

Service worker цепляется к активной вкладке через `chrome.debugger` и последовательно вызывает `Emulation.setDeviceMetricsOverride` на каждую ширину. Браузер честно пересчитывает layout: срабатывают media queries, container queries, `ResizeObserver`, обработчики ресайза.

Ключевое свойство: вкладка **не перезагружается**, поэтому сохраняются авторизация и текущее состояние SPA — открытая модалка, заполненная форма, результат кликов. Ровно это и есть смысл инструмента.

Цена: `debugger`-permission и плашка «DevTools is debugging this tab». Захват последовательный, примерно в пять раз дольше одного.

**Инвариант надёжности:** `detach` и сброс `Emulation` выполняются в `finally`. Вкладка пользователя ни при каком сбое не остаётся в эмуляции.

## Режим B — offscreen-iframe (fallback)

Страница снимается один раз, захваченные HTML и CSS клонируются в пять скрытых iframe'ов разной ширины, computed styles читаются из каждого. Media queries отрабатывают честно — это настоящий CSS в настоящем iframe.

Ограничение: JS не переигрывается. Layout, который дорисовывает скрипт, и lazy-контент приедут в desktop-виде на мобильной ширине.

Режим существует для случая «не трогай мою вкладку».

## Отклонено

Пять скрытых окон с реальной навигацией: это перезагрузка, теряющая состояние страницы после кликов. Плюс реальное окно Chrome не сжать до 390px.

## Дефолтные размеры

1920×1080, 1440×900, 1024×1366, 768×1024, 390×844. Редактируются в popup.
