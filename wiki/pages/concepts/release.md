# Публикация и обновление

Краткое саммари; пошаговая инструкция для владельца аккаунтов — [`docs/release/publishing.md`](../../../docs/release/publishing.md), тексты листингов и обоснования разрешений — `docs/release/listing.md`, политика приватности — `docs/release/privacy-policy.md`. Здесь только то, что определяет устройство релиза, а не последовательность кликов.

## Две площадки, обе руками

Chrome Web Store и Figma Community: ни у одной нет пути, который обошёл бы аккаунт владельца, поэтому загрузка — через их веб-интерфейс. Всё, что можно сделать до этого, делает `pnpm release` (`scripts/release.mjs`).

**Почему скрипт, а не инструкция.** Ошибки здесь тихие: забытый файл в zip — расширение не стартует у пользователей, и видно это только по отзывам; source map в zip — лишние сотни килобайт и исходники наружу; версия поднята в одном манифесте из двух — магазин отвергнет или, хуже, примет старый код под новым номером. Поэтому каждый шаг **проверяется**, а не просто выполняется.

## Что проверяет и собирает `pnpm release`

1. **Версия совпадает в четырёх файлах**: корневой `package.json`, `packages/extension/package.json`, `packages/extension/manifest.json`, `packages/plugin/package.json`. Разошлась — отказ; править одной командой `pnpm release --set X.Y.Z`. У манифеста плагина Figma поля версии **нет** — номер версии плагина ведёт сама Figma при публикации.
2. Рабочее дерево чистое: артефакт должен соответствовать коммиту.
3. `pnpm test` целиком (typecheck, сборка, unit, e2e) — релиз собирается только из того, что прошло все гейты. `--skip-tests` только для пересборки на том же коммите; сборку он не пропускает.
4. **Zip расширения**, чей список файлов **выводится из манифеста**, а не пишется руками: service worker, popup, иконки, `web_accessible_resources`, плюс относительные `src`/`href` из самого `popup.html`; внешние ссылки из popup — отказ. Source map не попадают.
5. **Папка плагина** — `manifest.json`, `code.js`, `ui.html`. Проверяется, что `ui.html` ни на что внешнее не ссылается (Figma забирает только эти файлы), что в манифесте есть `documentAccess: dynamic-page` (требование Figma для новых плагинов) и `networkAccess` (без него публикация отвергается). Пути `main`/`ui` в выходном манифесте переписываются на плоские.

Напоминание в конце: пока `id` плагина не числовой (`webpage2figma-local-dev`), это нормально **только для первой публикации** — Figma присваивает `id` при ней, после чего число надо вписать в `packages/plugin/manifest.json`, иначе следующий релиз не будет распознан как обновление того же плагина.

## Манифесты

**Плагин.** `networkAccess.allowedDomains: ["none"]` с обоснованием: плагин не ходит в сеть, байты изображений приходят внутри `.w2f`, который выбирает пользователь (см. [[delivery]]). `documentAccess: dynamic-page`.

**Расширение** (MV3). Разрешения `debugger`, `scripting`, `activeTab`, `tabs`, `downloads`, `storage` и `host_permissions: <all_urls>`. `debugger` и `<all_urls>` вместе означают углублённую проверку магазином — это ожидаемо, а не повод их убирать: без `debugger` нет эмуляции брейкпоинтов ([[breakpoint-capture]]), без `<all_urls>` нет байтов картинок с CDN ([[extension]]). Добавление **нового** разрешения в обновлении отключает расширение у пользователей до их согласия — не добавлять без крайней нужды.

## Картинки листингов

`pnpm store-assets` (`scripts/make-store-assets.mjs`) → `release/assets/`: обложка Figma 1920×960, скриншот Chrome 1280×800, иконка 128. Собираются из **настоящих** частей: окно расширения на скриншоте — живой popup, снятый в Chromium с загруженным расширением, а не нарисованный макет; иконка — та же, что в манифесте. Рисовать «как будет выглядеть» нельзя: листинг обещает пользователю то, чего он не получит, а это как раз то, за что магазины снимают расширения.

## Обновление: площадки доставляют сами, но не одновременно

Пользователей ни о чём просить не надо. Chrome скачивает новую версию в фоне, проверяя обновления раз в несколько часов; каждая версия проходит review. Плагин Figma исполняется с её серверов — все пользователи получают новую версию при следующем запуске, после первого одобрения обновления публикуются сразу, откатиться пользователь не может.

**Расширение и плагин обязаны выходить парой при смене `IR_VERSION`.** Формат бандла односверсионный ([[ir-bundle]]): плагин отказывается читать бандл чужой версии и говорит «пересними». Обновление одного без другого ломает импорт у всех, у кого второй ещё старый. Поскольку Chrome доставляет за часы, а Figma мгновенно, порядок фиксирован: **сначала расширение, дождаться одобрения, потом плагин.**

Порядок каждого релиза: `pnpm release --set X.Y.Z` → коммит → `pnpm release` → zip в Developer Dashboard, папка плагина через *Publish new version*.

## Установка без магазинов

Расширение — распакованный zip через *Load unpacked* (автообновлений нет); плагин — *Import plugin from manifest*, виден только в этом аккаунте.

**Сверка 2026-09-22:** `publishing.md` утверждал, что импорт манифеста доступен только в десктопном приложении, тогда как [[figma-semantics]] фиксирует импорт в браузерной Figma как подтверждённый запуском. Формулировка в документе исправлена: шаги описаны для десктопа как для проверенного пути, без утверждения, что браузер не умеет.
